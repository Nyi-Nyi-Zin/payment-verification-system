# Local Tesseract best models

The receipt OCR setup now installs English and Myanmar `tessdata_best` models from official revision `e12c65a915945e4c28e237a9b52bc4a8f39a0cec`. Existing fast model files are replaced by running `pnpm setup:ocr` in `backend/`; restart the backend after upgrading. Docker builds use the same setup script.

SHA-256 checksums:

| Language | SHA-256 |
| --- | --- |
| English | `8280aed0782fe27257a68ea10fe7ef324ca0f8d85bd2fd145d1c2b560bcb66ba` |
| Myanmar | `629dc3ab7adf4321f329d99f8c737d920308df7519734e36277b773c24df0699` |

The installed Tesseract.js/core 7.0.0 relaxed-SIMD build aborted on these float models with `missing function: tesseract::DotProductSSE` under Node 24.22.0. A compiled, isolated OCR worker disables relaxed-SIMD detection before loading Tesseract's Node worker, preserving its normal SIMD/non-SIMD selection. This follows the workaround documented in [upstream issue 1080](https://github.com/naptha/tesseract.js/issues/1080) and keeps runtime model loading offline.

Verification:

- Both installed model files passed pinned SHA-256 verification through `node backend/scripts/setup-ocr.cjs`.
- Backend unit tests: 14 suites, 63 tests passed after the worker change.
- Backend `npm run build` passed and emitted the custom worker.
- The compiled production OCR adapter read one existing local KBZPay receipt using both real best models. Provider, amount, date and time were extracted; the complete transaction reference matched the manually established reference. Cold recognition took approximately 2.4 seconds on this machine. Private receipt text was not printed.
- The existing local backend on port 3000 was restarted from this workspace's rebuilt `backend/dist/main.js`. Startup completed without stderr output; `/api/v1/health` returned HTTP 200 and the Payment Desk page returned HTTP 200.
- Real headless Chrome loaded Payment Desk after restart with zero page exceptions and fetched the health API successfully from the browser. No user receipts or payment records were created or modified by these checks.

The single receipt is a compatibility smoke check, not an accuracy benchmark or proof of improvement over fast models. Docker, deployment and broad receipt accuracy were not verified by this change. Previously saved OCR results are retained; subsequent OCR runs record `tesseract.js-7.0.0/eng+mya-best-e12c65a9/sparse`.
